【来源woshipm.com/ai/6266459.html《上下文工程探秘：超越提示词，AI产品经理必须掌握的核心技能》（@Tracy，引 LangChain/Cognition 博客）】核心观点：从"提示词工程"进化到"上下文工程"（Context Engineering）；Karpathy 类比：LLM 是 CPU，上下文窗口是 RAM（工作内存）。
不受控长上下文的挑战：①超出上下文窗口（如 200K tokens 上限）②成本与延迟激增（API 费用与输入 token 直接挂钩）③模型性能下降：Drew Breunig 总结四种退化——上下文中毒(context poisoning，前步幻觉被保留污染后续推理)、上下文分心(context distraction，信息淹没训练知识)、上下文混淆(context confusion，无关信息误导)、上下文冲突(context clash，相互矛盾信息导致前后不一致)。
Cognition 的两条原则：原则一"共享上下文，且是完整的 agent trace"（子任务只传目标不够，需知道全貌与他人已完成工作）；原则二"行动承载隐性决策，冲突的决策导致糟糕结果"（如一个子 agent 选像素风、另一个选卡通渲染）。并指出多智能体架构"决策权过于分散、上下文无法彻底共享"，可靠性不高。
四项策略：Compress 压缩（如不同 agent 交接时总结上下文以降低通信成本）、Write 写入、Select 选择、Isolate 隔离（多智能体各自独立上下文窗口；环境隔离/代码沙箱，如 HuggingFace CodeAgent 代码在沙箱执行，只有返回值传回 LLM）。
对 PM 的意义：Compress 直接对应 API 成本与延迟（产品经济可行性）；Write/Select 是长期记忆与个性化的基石（影响留存）；Isolate 是可扩展性的关键。参考来源：blog.langchain.com/context-engineering-for-agents/、cognition.ai/blog/dont-build-multi-agents。

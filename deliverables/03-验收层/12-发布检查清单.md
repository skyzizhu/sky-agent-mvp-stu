# 12 发布检查清单（Go / No-Go）

> **给谁看**：产品、研发、测试三方 ｜ **什么时候用**：每次版本发布前
> **一句话**：五项全过才允许发布；任一不过 = No-Go，修完重走清单。

| 5 | 文档同步 | README 流程图、realize.md、deliverables 与代码一致 | 【通过/不通过】 |

## 三、回滚策略

发布以 git 标签为原子单位。出现严重缺陷时按序执行：

1. **停止**：`./stop.sh` 停止工作台
2. **回退**：`git checkout 上一发布标签` 回退代码
3. **重启**：`./start.sh` 重启服务
4. **验证**：评测快跑（--n 3）确认恢复上一基线
5. **确认数据**：日志、事件存档、会话数据不受回滚影响（均为运行时追加文件）
6. **归因**：回滚后 24 小时内完成缺陷归因，修复后重走本清单

## 四、发布纪律

- 不允许「先发再修」——评测红线（-0.05）是硬门槛
- 回滚不是失败：带着已知缺陷上线的代价远大于回滚
- 每次发布在变更日志（15-变更日志.md）追加一行

# 04 Agent Spec 编排规格（AI PM 的核心签名交付物）

> **给谁看**：研发（实现依据）、未来的自己（决策记录） ｜ **什么时候用**：实现编排、评审改动、交接项目
> **一句话**：定义「每个决策点谁判断、判断错谁兜底、模型每轮看到什么、每个动作怎么留痕」——改任何一条都要过评测回归。

## 一、决策权分配矩阵（编排的核心契约）

| 决策点 | 判断者 | 边界依据 | 判断错误的兜底 |
|---|---|---|---|
| 子问题拆解（数量、查证要点） | 模型 | 规划提示词硬性约束（不超过 3 个） | 解析失败降级空大纲，继续执行 |
| 每步调用哪些工具与参数 | 模型 | 工具说明书（描述与 Schema） | 异常转可行动错误文本回填 |
| 笔记写入的内容与时机 | 模型 | 提示词要求随手沉淀 | 上下文压缩与笔记兜底 |
| 子问题核销（显式） | 模型 | update_checklist 工具 | 笔记感知自动核销兜底 |
| 哪些评审意见需要补查、查什么 | 模型 | 修订策划调用（次数受限） | 策划失败降级纯改写 |
| 预算水位触发（80/95/100%） | 代码 | 真实 token 计量 | 到线必停，不依赖模型自觉 |
| 强制收尾的触发与执行 | 代码 | 看板全绿/死线/硬收尾水位 | 笔记原文兜底报告 |
| 熔断触发（连败 4 次，至多 2 次） | 代码 | 失败计数器 | 超限后停止重试 |
| 上下文压缩的触发与执行 | 代码 | usage 真实计量超阈值 | 压缩失败保留原历史 |
| 危险动作的最终执行 | 人 | 确认卡（600 秒超时视为拒绝） | 拒绝回执引导模型改道 |

原则：需要语言理解与灵活判断的交给模型；需要确定性与时序保证的交给代码；不可逆动作的最后决定权交给人。**每个「模型判断」必须配「错误兜底」**——这是本表的验收线。

## 二、系统提示词规格（规则与意图对照）

系统提示词共 7 条硬性规则，每条的「意图」如下（改任何一条前先看意图）：

| 规则 | 内容摘要 | 设计意图 |
|---|---|---|
| 1 查证禁止编造 | 用工具查证，禁止凭记忆 | 对抗幻觉 |
| 2 随手笔记 | 关键发现立即 note_write；收尾前必须 note_read | 对抗上下文丢失 |
| 3 引用格式 | 每个事实紧跟 [n](url)，文末参考小节 | 结论可溯源 |
| 4 充分度收敛门禁 | 主干有据即止，严禁为完备漫游 | 对抗无限发散 |
| 5 数字纪律 | 数字逐字来自证据，无证据标「未验证」 | 对抗编造数字 |
| 6 摘要优先 | snippet 够用就直接引用，不盲目开网页 | 降低成本 |
| 7 信源分歧处理 | 优先一手官方；冲突必须披露，严禁取平均 | 对抗抹平冲突 |

## 三、工具规格（ACI——模型的产品界面）

| 工具 | 用途 | 关键参数 | 返回与限制 | 危险分级 |
|---|---|---|---|---|
| web_search | 联网检索（Tavily 优先，免费引擎降级） | query | 结构化结果列表，头尾保留截断 | 只读 |
| fetch_url | 静态网页抓取（正文抽取） | url | 纯文本正文，截断 4000 字符；SPA 自动降级 | 只读 |
| fetch_js | 无头浏览器 JS 渲染抓取 | url, wait_ms | 渲染后正文（含页脚），头尾保留截断 | 只读（资源重，走缓存） |
| note_write | 沉淀调研笔记（自动核销看板） | content | 确认文案 | 写入会话本地笔记 |
| note_read | 读取当前会话全部笔记 | 无 | 笔记全文 | 只读 |
| update_checklist | 显式核销子问题 | sub_id, status, summary | 更新确认与看板事件 | 只读 |
| MCP 外部工具 | 按 MCP_SERVERS 配置动态接入 | 由外部 server 定义 | 拼接文本回填 | 写类自动进危险分级走 HITL |

工具描述（description）的一句话增删都会改变模型行为——**任何工具改动必须跑评测回归**。

## 四、上下文预算表（模型每轮看到什么、多大）

| 组成部分 | 内容 | 量级 |
|---|---|---|
| 系统提示词 | 7 条规则 + 研究大纲 + 记忆注入 + 会话上下文 | 1500-3000 token |
| 历史消息 | 压缩后为摘要 + 最近 6 条原文 | 被压缩机制约束在阈值内 |
| 本轮注入 | 进度行 + 看板文本 | 200-500 token |

## 五、护栏规格

护栏四层 + 预算三水位 + 熔断 + 兜底链的完整规格见 [../02-设计层/10-护栏规格.md](../02-设计层/10-护栏规格.md)。

## 六、修改规则

1. 本规格任何修改 = 一次「改前基线 / 改后回归」双跑评测
2. 决策权矩阵新增或移动决策点，必须同步更新状态机与事件契约
3. 提示词规则修改须注明「对抗哪种失败」（无失败案例不加规则）

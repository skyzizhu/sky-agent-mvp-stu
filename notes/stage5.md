## 踩坑实录（2个，都很有价值）
1. **agent 不会自己收敛**：连续两次步数耗尽，模型 endless 调研（16步全是点菜，从不停下来写报告）
   → 修复：runtime 在倒数第2步注入死线消息"立即 note_read 并输出报告"
   → **认知：收敛是确定性代码的职责，不能指望模型自觉**——这是 agent 工程最重要的一课
2. **规划器贪多**：大纲被写成完美主义清单（缓存价/错峰折扣/限流全要查）→ 永远做不完
   → 修复：prompt 硬性限制"子问题≤3个、10步内可完成"
   → **认知：规划质量决定收敛性；给 agent 的计划必须带预算意识**

## 收敛护栏的完整设计（值得记住的模式）
```
runtime（确定性代码）:
  剩2步时 → 注入 user 消息："⚠️时间将尽，立即 note_read + 输出报告"
  步数归零 → 强制退出 + 汇报已有进展
```
这和 max_steps 一样，属于"模型负责聪明，代码负责兜底"的分工。

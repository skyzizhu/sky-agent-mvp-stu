# 14 术语表

> **给谁看**：所有人 ｜ **什么时候用**：遇到不懂的名词
> **一句话**：项目全部行话的大白话解释。

| 术语 | 全称/类别 | 大白话解释 | 项目落点 |
|---|---|---|---|
| HITL | Human-In-The-Loop | 人在回路：危险动作执行前暂停，等人批准 | 确认横幅、/approve 端点 |
| SSE | Server-Sent Events | 服务器向浏览器单向实时推送事件的传输方式 | 执行流实时刷新 |
| MCP | Model Context Protocol | 接入外部工具生态的标准化协议 | mcp_client.py |
| token | 词元 | 模型的计量与计费单位 | 预算三水位 |
| LLM | Large Language Model | 大语言模型 | 全项目主角 |
| DSML | （项目内称呼） | DeepSeek 泄漏的内部工具调用标签 | _clean_report 净化 |
| JSONL | JSON Lines | 每行一个 JSON 的文件格式 | runs.jsonl、事件存档 |
| SPA | Single Page Application | 靠 JS 渲染的网页（静态抓取只有壳） | fetch_url→fetch_js 降级 |
| ACI | Agent-Computer Interface | 工具接口设计=给 AI 的产品界面 | 工具菜单卡规范 |
| GUI / CLI | 图形界面 / 命令行界面 | 两种宿主形态 | 工作台 / 终端 |
| groundedness | 有据性 | 结论被原始证据支撑的程度 | 评测灵魂维度 |
| rubric | 评分标准 | judge 打分的维度定义与锚点 | 四维 rubric |
| trace | 运行轨迹 | 一次运行的完整消息流存档 | traces/ 与事件存档 |
| Context Rot | 上下文腐烂 | 对话越长模型越忘早期内容 | 萃取/压缩对抗它 |
| Relevance Gating | 相关性门禁 | 记忆按意图/实体过滤后才注入 | 防记忆负迁移 |
| Compaction | 历史压缩 | 旧消息 LLM 摘要化 | 5.2 小节点 |
| Snippet-First | 摘要优先 | 搜索摘要够用就直接引用 | 提示词规则 |
| Evaluator-Optimizer | 评估-优化模式 | 草稿→评审→修订循环 | 反思模式 |
| Orchestrator-Workers | 编排者-工人 | 拆题→并行 worker→汇总 | 多智能体 |
| Plan-and-Execute | 计划-执行 | 先规划再逐步执行 | 大纲+看板模式 |
| fail fast | 快速失败 | 缺配置第 0 秒报错 | make_client |
| ⚠P 编号 | PITFALLS 编号 | 文档中的坑位引用 | PITFALLS.md |

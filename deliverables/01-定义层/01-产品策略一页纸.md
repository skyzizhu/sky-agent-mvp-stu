# 01 产品策略一页纸

> **给谁看**：老板、团队、未来的自己 ｜ **什么时候用**：项目 kickoff、方向摇摆时回看
> **一句话**：这个产品给谁解决什么问题，凭什么赢。

## 给谁

需要快速完成竞品、行业、政策、技术调研的知识工作者。**首位人群：产品经理**——他们每天要做大量「对比 A 和 B」「查最新政策」「摸清一个技术方案」的调研，每次 2-4 小时。

## 解决什么问题

| 现状痛点 | 根因 | 我们的解法 |
|---|---|---|
| 调研耗时 2-4 小时 | 多源检索 + 交叉验证 + 整理成文全是人工 | agent 自主完成全流程，压缩到几分钟 |
| 通用 LLM 直答不可信 | 知识截止、无来源、编造 | 实时检索 + 强制引用 + 证据核对评测 |
| 过程是黑盒，不敢用 | 看不到 agent 干了什么 | 执行流逐颗粒实时可视、可回放 |
| 成本不可控 | token 消耗不透明 | 四档预算 + 到线必停 |

## 凭什么赢（差异化）

1. **过程透明是产品**：执行流按「步.动作」编号实时直播，每颗粒可下钻看完整输入输出——不是调试特权，是用户权利
2. **强制引用 + 证据核对评测**：结论必须挂来源，评测系统专抓编造——「可信」从口号变成机制
3. **收敛的物理保证**：看板核销、预算硬收尾、熔断器全部硬编码，不靠模型自觉
4. **多轮会话**：同话题追问不重复检索，研究是连续对话

## 北极星指标

**评测总分 ≥ 0.80**（12 题 LLM-as-judge，四维均值）。当前 0.66，历史从 0.57 起步。
配套护栏指标：有据 ≥ 0.70、有源 ≥ 0.90、标准档单题 ≤ 6 万 token、零空报告。

## 不做什么（本版明确排除）

- 邮件投递（已完整实现又按 MVP 聚焦原则移除，教训见 PITFALLS 与 git 历史）
- 多租户 / 账号体系（单用户本地工作台定位）
- agent 自我修复（归因学习是本项目的核心目标，不做自动化）

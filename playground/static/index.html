构造请求 → 看原始响应。所有字段一字不删，报错也是教材。

模型与连接

messages 数组

+system +developer +user +assistant +tool(带id)
实验建议：① developer 和 system 同时放，看模型听谁的；② 构造一条 assistant(tool_calls) + 对应 tool 消息，体会回填配对；③ 故意删掉 tool 消息里的 tool_call_id 看 400 报错。

tools 说明书（JSON数组，可留空）

示例：天气+计算器 示例：烂描述（对比实验） 清空

请求参数

留空的参数不会出现在请求体里——发出的请求永远所见即所得。

原始响应（API 返回的原文，未做任何处理）

（左侧构造请求，点"发送请求"；这里会显示：
  1. request_sent —— 实际发出的完整请求体
  2. status —— HTTP 状态码
  3. raw —— API 返回的原始文本（含 content / reasoning_content /
     finish_reason / tool_calls / usage 全部字段；报错时是错误原文））

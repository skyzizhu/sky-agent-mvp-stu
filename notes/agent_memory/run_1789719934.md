AWS官方博客《Agentic AI基础设施实践系列六：Agent质量评估》(aws.amazon.com/cn/blogs/china/agent-quality-evaluation)：评估四层必要性=技术/业务/伦理合规/迭代；指标分业务类（任务完成率TCR、决策准确率、工具调用正确率）、效率类（平均任务耗时、平均交互轮数）、安全类（+成本）；RAG类可评召回率/精确率/NDCG；评估四步=定义目标指标→用真实场景数据建测试集（复杂多步任务要建完整推理步骤）→执行分析（最准是人工评估，更省的是LLM as judge，关注是否选对工具/上下文信息是否正确/事实是否准确）→优化测试集迭代评估；三大框架：AgentBench（跨环境泛化）、AgentBoard（决策过程细粒度分析）、τ-bench（真实业务场景可靠性）；强调常规+边缘+对抗性测试集，"评估→优化→再评估"闭环；局限：内容有效性/合理性判断与用户体验仍需人工。

OpenAI《A practical guide to building agents》（中文译文 lewlh.github.io）：面向产品与工程团队，34页；智能体三核心组件=模型/工具/指令；LLM不控制工作流执行的（聊天机器人、单轮、情感分类）不算智能体；适合场景三类=复杂决策（退款审批）、难以维护的规则集（供应商安全审查）、高度依赖非结构化数据（理赔）；三类工具=信息检索/执行/编排（agent as tool，管理者模式）；模型选择原则=先建评估定基准→优先最强模型→再换小模型优化成本延迟；防护措施guardrails含输入过滤、工具使用、人工干预；人工干预两种触发=超出失败阈值、高风险操作；主张从单智能体开始、按需演进多智能体、小规模起步与真实用户验证。

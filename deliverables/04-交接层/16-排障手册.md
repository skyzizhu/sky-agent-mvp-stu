# 16 排障手册

> **给谁看**：值班/排障的人 ｜ **什么时候用**：agent 表现异常时
> **一句话**：先分层（没做 vs 没显示），再按症状查表。

## 第一步：分层诊断（最重要的一个动作）

```
用户报障「没有报告/没反应」
    ↓ 查 logs/runs.jsonl 有没有该 run_id 的收尾记录
    ├─ 有收尾记录 → 传输层问题（显示/管道坏了），内核是好的
    │                → 处理：重连/回放即可拿到报告
    └─ 无收尾记录 → 内核层问题（真的没做完）
                     → 查 events_{run_id}.jsonl 最后一条事件，定位卡在哪
```

## 症状查表

| 症状 | 可能原因 | 排查与处理 |
|---|---|---|
| 报告页空白 | final 事件无 answer；或前端渲染异常 | 查存档 final 事件；检查浏览器控制台 |
| 实时流中断（前端提示） | 长静默被 WebView/代理掐断（已带心跳+重连，仍发生则看网络） | 运行仍在后台继续 → 稍后从历史回放 |
| 报告含内部标签（DSML） | 硬收尾路径模型吐内部语法 | _clean_report 已覆盖已知变体；新变体补充正则（PITFALLS） |
| 反复搜索同一关键词 | 模型不收敛 | 已有熔断+自检；确认看板注入正常（progress 事件） |
| 预算未到就停 | 步数死线或用户中止 | 查 stop_reason；max_steps 属正常 |
| 工具连续报错 | 外部源故障/反爬 | 熔断器会介入；更换信源或稍后重试 |
| 报告数字与来源不符 | 编造 | 数字纪律已强制标注；发现漏网即补评测题 |
| 追问轮重复检索 | 会话未生效 | 检查 session_id 是否随请求传递 |
| 会话历史重复记录 | 重复注册（已修复） | 检查是否有旧版本代码在跑 |

## 诊断工具

| 工具 | 位置 | 用途 |
|---|---|---|
| runs.jsonl | logs/ | 收尾记录（分层诊断第一步） |
| 事件存档 | logs/events/events_{run_id}.jsonl | 逐颗回放（每行一个事件） |
| DEBUG_DUMP | 环境开关 | 硬收尾等关键路径 dump 消息结构（防 400 排查） |
| 评测快跑 | run_eval.py --n 3 | 改动后快速验证 |
| 观测面板 | observatory/ | 成功率/成本/失败分布三问 |

## 三条铁律

1. **先分层，再定位**：没做 vs 没显示，方向错了全白干
2. **单题分数异常 ≠ 系统坏了**：先重跑，看均值
3. **修复必须过回归**：任何修复后重跑评测，确认修复且不伤其他题

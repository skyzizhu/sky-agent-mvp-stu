第 0 步 · 启动准备（只执行一次）

N00用户输入与启动校验 前端

用户提交研究问题 + 预算档位（快问 2 万 / 标准 5 万 / 深度 12 万 / 不限）。
校验：问题非空；档位无效回落标准档；服务不可用时报错并保留输入。
展开细节
前端把 session_id 一并提交（空 = 新会话）。运行注册只在这一步做一次（每轮恰好记录一次，防止重复）。 运行线程启动后，SSE 通道建立，前端进入实时视图。
▼

N01 · 0.1记忆注入（长期偏好）

从 memory.json 召回用户稳定偏好，经相关性门禁过滤后拼入 system。
门禁规则：通用偏好（语言/格式/研究规范）全量注入；领域偏好（定价/合规等）须同时命中「意图关键词 + 实体交集」才召回——防止上次的定价偏好污染这次的技术调研。
展开细节
事件 memory_inject 携带 {count, total, filtered}。空记忆或全不相关 → 注入空串，不占 token。 记忆来自历史会话结束时的自动提取（只收用户稳定偏好，研究内容严禁混入），合并走 LLM 语义去重、上限 20 条。
▼

N01+会话上下文注入（多轮时）

同一会话的第二轮起：注入上轮摘要 + 关键发现 + 共享笔记——模型「知道上次研究到哪了」。
展开细节
来源：context.json 快照（每轮结束保存：摘要 / 关键发现 / 待办）+ sessions/{sid}/notes.md 前 2000 字。 新会话此节点为空。
▼

N02 · 0.2预算与安全边界初始化

建立预算记账（档位上限）、步数上限 20、危险工具清单公示。
三水位：预算 80% 软提醒 → 95% 硬收尾（物理摘除工具箱） → 100% 强停只允许结题/笔记兜底。
▼

MCP 外部工具接入（可选）

按 MCP_SERVERS 配置接入外部工具生态；写类工具自动进危险分级，执行前必须 HITL。
▼

N04 · 0.3研究规划（独立 LLM 调用）

规划师把问题拆成 ≤3 个带查证要点的子问题（JSON mode）。规划-执行分离：规划师不看工具箱。
失败降级：解析失败 → 空大纲继续，不阻塞主流程。
展开细节
0.3 事件带五区块详单：① 规划调用的完整请求 JSON ② 模型全字段输出 ③ token 明细 ④ 子问题拆解 ⑤ 大纲原文。 规划质量 = 后面 20 步的走向，PM 应亲自审规划输出（是否覆盖用户意图、是否互相独立）。
▼

N05 · 0.4大纲落地（三份产物）

同一份大纲落地为：① system 追加【研究大纲】（每轮可见，对抗遗忘）② 动态看板（子问题状态机：待查证/查证中/已完成）③ final 返回值（评测核对覆盖度用）。
▼ 进入主循环
主循环 · 第 1~20 步（一圈一结清）

N06 · 每轮开头注入进度与看板

把「第 N/20 步 · 预算水位 + 看板状态（[x]已完成 / [~]查证中 / [ ]待查证）」拍给模型。
全绿触发：追加「🎉 全部核销完成，立即输出报告，严禁继续检索」——收敛的物理信号。
阶梯自检：step≥4 或预算≥50% 追加「主干有据即止」提醒；step≥19 追加死线警告。
▼
用户点了 ⏹ 中止？
是（仅一次）注入收尾指令（user_stop），循环继续——模型停止点菜，转为输出报告
否继续
▼
死线（第 19~20 步）或预算过 80%？
是注入死线 / 软提醒（各一次）——实测可能被无视，后续有硬收尾兜底
否正常继续
▼

N07调用 LLM（带工具说明书）

模型基于「system 规则 + 大纲 + 记忆 + 全部历史 + 本轮注入」自主决定：调用哪些工具、参数是什么。
留档：step 事件携带完整请求 JSON（messages 全量）、模型全字段输出、token 四项明细——压缩前后的对比学习就看这里。
▼
调用协议异常？（网络/限流/格式）
是error 出口——错误记入日志，循环外兜底链接管
否继续
▼
无 tool_calls 且正文有效？
是model_done 出口——正文即报告（唯一优雅出口，任何一步都允许发生）
否（还有点菜）先过预算硬收尾判断 ↓
▼
预算 ≥95% 或已耗尽？
是budget_hard_stop 出口——① 先抢救未执行的笔记落盘 ② 摘除未应答点菜（协议自愈）③ 拔掉工具箱（请求不带 tools，物理上无法再调）④ 笔记全文嵌入结题指令 ⑤ 无工具强制结题
否进入上下文检查 ↓
▼
本轮输入 token > 压缩阈值？（窗口 1M × 60% = 600K）
是上下文压缩：旧对话交给摘要模型（保留目标/发现含来源/待办/约束，≤800 字）→ 重建为 [system + 摘要 + 最近 20 条原文]。压缩调用自身全量留档、计入预算
否直接执行工具 ↓
▼

N08-N20逐个执行工具（一圈一结清）

检索（Tavily 优先，免费引擎降级；Query 去重）→ 网页抓取（静态失败自动降级无头浏览器；域名失败≥2 次改道）→ 单页萃取（>800 字触发，压减 80%+）→ note_write（写盘 + 自动核销看板）→ 结果逐条回填（tool_call_id 配对）。
展开细节
危险工具命中 → 暂停弹确认横幅（参数 + 原因），批准执行 / 拒绝回执引导改道，600 秒超时视为拒绝。
核销联动：note_write 内容命中「子问题 X」→ 看板自动核销并附结论摘要。
检索类结果进入证据池（评测 judge 只对照这些原始证据打「有据」分）。
预算死线抢救：若本轮之后触发硬收尾，未执行的 note_write 会被自动抢救落盘，发现不随裁剪丢失。
▼
工具连续失败 ≥4 次？
是（至多 2 次）注入熔断指令：禁止重复同方式，基于已有信息出阶段结论
否回主循环开头，进入下一轮 ⟲
收尾 · 五出口汇合与兜底链
✅ model_done — 模型停止点菜、正文有效（唯一优雅出口）
🛡️ budget_hard_stop — 预算 95% 拔工具强制结题
⏹ user_stop — 用户中止后模型收尾
🔢 max_steps — 20 步耗尽强制结题
❌ error — 协议异常，循环外兜底
▼ 五路汇合，执行兜底链

兜底链（保证交付物非空）

判断 1：已持有有效报告？→ 是则直接进入交付。
判断 2：否则发一次无工具强制结题调用（笔记全文嵌入指令，模型物理上无法再检索）。
判断 3：仍无效 → 笔记原文直接兜底成报告——「查到什么就交付什么」，绝不全损。
▼

收尾三件事

记忆：LLM 从 transcript 提取用户稳定偏好（严禁混入研究内容）→ 语义合并进 memory.json；
会话：保存上下文快照（摘要/关键发现/待办）供下轮注入；
日志：RunLog 落盘（步数/工具序列/token/停止原因/错误清单）。
▼

N28🏁 final 事件：报告输出

报告全文（含 [n](url) 引用与参考小节）推送前端渲染；若为阶段性结题，末尾附「当前未完成项 / 下一步」。
贯穿全程的三条横切线（不属于任何单一步骤）

① 外置记忆（note_write / note_read）

发现随手写入磁盘（不受压缩影响）→ 看板自动核销 → 收尾读回成文（硬收尾时系统直接嵌入）。事实永远在「上下文或磁盘」之一，不存在丢失态。
▼

② 评测体系（独立于运行）

12 题三件套，四维评分（有据/有源/覆盖/简洁），judge 只对照原始证据（不上网）；改前改后双跑，任一维度降 0.05 阻断发布。当前基线 0.66，目标 ≥0.80。
▼

③ 可观测（贯穿每一步）

18 种事件全量留痕（实时 + 存档），颗粒可下钻全量 IO；排障口诀：先查运行日志有无收尾记录——有 = 传输层问题，没有 = 内核问题。

# 09 数据字典

> **给谁看**：研发（前后端契约）、数据分析 ｜ **什么时候用**：实现事件/日志、做数据统计、排查问题
> **一句话**：三份数据的结构定义——运行日志、事件流、会话存储。

## 一、运行日志（logs/runs.jsonl，每行一条 JSON）

| 字段 | 类型 | 说明 |
|---|---|---|
| run_id | string | 运行唯一标识（8 位十六进制） |
| ts | string | 开始时间 |
| impl | string | 宿主标识（webapp/cli/…） |
| question | string | 研究问题（截 80 字） |
| steps | int | 实际执行步数 |
| tool_calls | array | 工具调用序列（按执行顺序） |
| tokens | int | 实际消耗 token |
| budget_max | int/null | 预算上限（null=不限） |
| stop_reason | string | model_done / budget_hard_stop / user_stop / max_steps / error |
| errors | array | 错误清单 |
| extra | object | 扩展：new_preferences（提取偏好）、session_id（会话溯源） |

## 二、事件类型枚举（事件流与存档 events_{run_id}.jsonl）

| 事件 | 载荷要点 | 消费方 |
|---|---|---|
| run_meta | run_id/session_id/question | 回放溯源（存档头部第一条） |
| memory_inject | count/total/filtered/text | 前端卡片 |
| guardrail | max/dangerous | 前端卡片 |
| mcp | msg | 前端卡片 |
| plan | outline/goal/sub_questions/ms/prompt_tokens/detail | 规划卡片（五区块详单） |
| progress | text/checklist | 进度注入留痕 |
| step | step/tools/prompt_tokens/model_ms/total_messages/detail | 模型调用颗粒（三区块详单） |
| tool_result | name/result/full_result/args/tool_ms/cache_hit/extracted/… | 工具颗粒与徽章 |
| checklist | items/completed/total | 看板卡片刷新 |
| inject / budget / breaker | note/used/max | 护栏动作留痕 |
| compact | before/after/stats/summary | 压缩颗粒 |
| approval_request / approval_result | tool/args/reason/approved/receipt | 审批闭环 |
| backfill | count/items | 回填确认 |
| memory_extract / memory_saved | prefs/transcript/added | 记忆颗粒 |
| forced_final | ms/output/error | 强制结题记录 |
| final | answer/steps/used/stop_reason/total_ms | 报告与汇总 |
| error | message | 错误卡 |
| done | —（服务端合成，不入存档） | 收流标记 |

## 三、会话存储（sessions/{sid}/ 目录）

| 文件 | 结构 | 用途 |
|---|---|---|
| meta.json | {session_id, created, topic, runs:[{run_id, question, ts}]} | 会话轮次注册（每 run 恰一条） |
| notes.md | 纯文本追加 | 会话共享调研笔记（跨轮续跑） |
| context.json | {summary, key_findings[], pending, saved_at} | 跨轮上下文快照（下轮注入 system） |

## 四、评测产物（evals/results/eval_日期_时间.md）

结构：总分与维度均分 → 逐题表（总分/四维/用时/主要问题）→ 各题答案全文。用于改前改后对比与人工复核。

## 五、契约规则

1. 事件新增字段 = 契约变更，须同步更新前端渲染与本文档
2. 存档每行一个 JSON（JSONL），追加写
3. run_meta 必须是存档第一条（回放溯源依赖）
4. 所有事件经 emit 深拷贝/规范化后入队——引用污染是历史事故源

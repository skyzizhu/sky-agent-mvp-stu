【子问题4 缓存计费规则】来源: api-docs.deepseek.com/zh-cn/guides/kv_cache（上下文硬盘缓存）
- 硬盘缓存对所有用户默认开启，无需改代码；每次请求都会触发缓存构建
- 命中条件（官方表述）：前缀与之前请求重复且“完整匹配缓存前缀单元”才计入“缓存命中”；每条缓存前缀单元是独立完整单元
- 落盘时机三类：①请求的用户输入结束位置与模型输出结束位置各产生一个缓存前缀单元；②检测到多次请求公共前缀时，把公共前缀作为独立单元落盘；③长输入/长输出中按固定 token 间隔截取缓存前缀单元落盘
- 典型可命中场景：多轮对话追加轮次；长文本问答中 system+固定文档内容构成公共前缀（前两次不命中，第三次才命中）
- 计量字段（官方）：响应 usage 中新增 prompt_cache_hit_tokens（输入中命中缓存的 tokens）与 prompt_cache_miss_tokens（输入中未命中的 tokens）→ 即输入按命中/未命中两档分开计价
- 缓存 TTL：官方仅说“缓存不再使用后会自动被清空，时间一般为几个小时到几天”，无精确 TTL 承诺；缓存构建耗时秒级
- 官方明确“缓存系统是尽力而为（best effort），不保证 100% 缓存命中”
- 缓存不影响输出随机性（仍受 temperature 影响）

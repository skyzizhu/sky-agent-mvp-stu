Anthropic《Building Effective Agents》(anthropic.com/engineering/building-effective-agents)：核心观点——最成功的实现不用复杂框架，而用简单可组合模式（simple, composable patterns）；建议先找最简单方案，仅在需要时增加复杂度，很多场景单次 LLM 调用+检索+上下文示例就够；区分 workflows（预定义编排，可预测一致）与 agents（模型驱动动态决策）；agentic 系统用延迟和成本换任务表现；框架（LangChain 等）会带来抽象层，遮蔽底层 prompt/response 难以调试，建议直接用 LLM API；强调 agent-computer interface (ACI) 需像 HCI 一样投入，SWE-bench 项目优化工具的时间比优化 prompt 更多。

productmap.io/blog/ai-product-manager-skills：AI PM 技能 = 80% 传统 PM 技能 + 20% 新技能。传统→AI 的映射：需求文档(PRD)→spec+eval set（含 golden cases 与已知失败模式）；成功指标(上线打勾)→质量区间(quality range)；优先级(价值vs成本)→加入第三轴 每次调用成本 cost per call；用户研究→仍需 discovery+新的探查。三大习惯：把 spec 视为概率性的、用 eval set 定义验收标准；从第一天把数据和成本当一等输入；以真实使用而非 demo 效果评判 AI 产品。最大技能缺口=评测(evaluation)：会写 prompt 但不会定义"够好可发布"。数据素养必要，数据科学背景非必须。

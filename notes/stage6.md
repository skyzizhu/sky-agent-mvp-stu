# Stage 6 复盘：模式与取舍（2026-09-15）

## 做了什么
- `stages/06_patterns/patterns.py`：
  - `run_workflow()` 四段固定管道（模板拼词→搜→一次成文），无循环无决策
  - `run_reflective()` Evaluator-Optimizer（草稿→评审→修订，≤2轮，可提前退出）
- `stages/06_patterns/ab_experiment.py`：同一题集跑三种实现（workflow/反思/agent v3），
  同一 judge 评分，对比质量分/tokens/用时

## 实测数据
两题版（ab_0915_2206）：A 0.57 / B 0.55 / C 0.73（A、B token 未计量）
一题版（ab_0915_2211，修复计量后）：A 0.82·2.1k tok·46s / B 0.58·21k·106s / C 0.76·28k·65s

## 三个大结论（本次最有价值部分）
1. **agent 质量最高但最贵**：C 质量稳定 0.68-0.78，token 是 workflow 的 13 倍
   ——"质量差距小就选 workflow"有了自己数据支撑
2. **反思增强首跑翻车（B ≤ A）**：修订者只会纯文字改稿，评审员说"缺定价数字"它补不了
   （手里没工具），甚至把已有内容删了 → **Evaluator-Optimizer 的修订者必须能对意见
   采取行动（带工具重新调研），纯文字修订≈化妆品**
3. **单题噪声大**：同题两次运行分数差 0.2+，结论必须看多题均值，别被单次结果骗了

## 工程教训
- **统一入口才能统一观测**：A/B 直接调 client 绕过了 call_llm，录制器计量为 0；
  修复 = 给 call_llm 加 **extra 透传**，所有调用走同一扇门
- AGENT_NODES.md 的节点预告表在多次插入时被弄乱（孤儿表头）——
  长文档的结构性内容要用脚本或锚点维护，不能靠手拼
